status: approved

How this works, in plain language

Two parts talk in real time. The game page runs in each player's browser and draws the 2.5D school. The game server is the referee: it holds the true game and tells each phone only what that player may know.

Phones never decide anything important. They say "I moved," "I picked B," or "I vote Kevin." The server checks it, updates the game, and replies. That's how roles stay secret, and why the correct answer never leaves the server early. The same server delivers the page, so it's one program and one public URL. Games live in memory and vanish when they end.

Your unknown: "I never create 3d in react"

  • <Canvas> is a React component; JSX tags inside it become 3D objects.
  • Moving things don't use React state. useFrame runs every frame and moves objects through refs.
  • Models load with useGLTF inside <Suspense>, and the bean fallback plugs in there.
  • Build step 1 checks it: one room, a bean, the follow camera, joystick + WASD, smooth on desktop and phone, before any multiplayer.

Components

Shared game definitions shared/

Types, the typed event contract, the map (rooms, walls, 6 terminals, button, seats), questions, quick facts, and tuning constants. Both sides import them so they never disagree.

Game server, the referee server/
  • index.ts: Express + Socket.IO on one port; serves client/dist
  • rooms.ts: 4-letter codes (no O/0, I/1), max 5, "already started," host handoff
  • GameRoom.ts: one game's state and timers, written as plain methods so it's unit-testable
  • rules.ts: roles, tasks, vote tally, win checks (pure + Vitest)
Avatar setup client/avatar · shared/avatars.ts

Rotating 3D preview on the home screen; pick one of 4–6 CC0 characters, 5 colors, and a name. Saved in localStorage (not Google sign-in, which is Later). Bean variants if packs lack characters.

Menu, join & lobby client/screens

Create / Join; ?room= shows "Join ABCD" after the avatar step; copy link; host-only Start at 4+ with "Need X more."

Role reveal RoleReveal.tsx · audio/typing.ts

Classroom scene behind an open book. Character on the left page, role + typed quick facts on the right. Web Audio clicks start after the "Open your book" tap.

School scene (3D) client/game

<Canvas>, toon materials, low walls, CC0 furniture, characters (model or bean), glowing terminals and button, fixed follow camera, local movement + collision, remote interpolation.

HUD & controls client/hud

Custom joystick (touch) + WASD/arrows (desktop), strikes and progress bar, task list, context action button (Use / Meeting).

Study-Bot terminal panel ★ terminal/

Question, countdown from the server's deadline, Study-Bot's confident chat bubble, 4 answers, Double-check, Verify (Fact-Checker), Hack (Bluffer), and the result flash.

Meeting, chat & vote Meeting.tsx · VoteResult.tsx

Chat (140 characters max), vote buttons + Skip, 90s countdown, who has voted (not for whom), then the result line.

Game over GameOver.tsx

Winner headline, every role revealed, back to menu.

Connection & store net/

One typed Socket.IO client; a Zustand store for screen, role, tasks, question, chat, votes. App.tsx picks the screen by phase.

When it breaks · what we simplified

Failure modes 5
  • Server waking or unreachable → "Connecting to school…" banner, auto-retry
  • Model won't load → bean fallback for that object
  • No WebGL → plain "can't show 3D" message
  • Disconnect / refresh mid-game → treated as eliminated; win check runs; lobby host hands off
  • Sound blocked → typing still animates silently
Simplifications 8
  • Phones report their own movement; server trusts it (no anti-cheat)
  • Games in memory, no database
  • No reconnection: refresh means leaving
  • Pre-written questions (live AI is Later)
  • Low walls instead of see-through shaders
  • Synthesized typing sound
  • Avatar saved on the device instead of Google sign-in
  • Custom joystick + keyboard, no library
