App Map: Who Hacked the Bot?

A take-home guide to how the game is built and where to change things. Snapshot of commit b863232; the code may drift after this.

What the app is

A browser party game about not trusting AI blindly. Players walk a 3D school, find pieces of quiz questions, and answer them at terminals with the help of Study-Bot, an AI study assistant. One player is secretly the Bluffer, who hacks Study-Bot so it gives confident wrong answers, and can expel classmates. The class holds meetings, talks, and votes out whoever they think did it. In Practice mode you play against 3 bots, and you can talk to them in meetings.

The rules and the school

Map, rooms, hiding spots, questions, timings, and vision. Both the server and the browser read these files, so they always agree.

server/

The referee

GameRoom decides everything that counts: who holds which piece, hacks, expels, votes, and who wins. Also the practice bots and the Claude calls.

client/

What you see

React screens (menus, meeting, terminal, Game Over), the 3D school (React Three Fiber), and the on-screen HUD. It sends your actions and shows what the referee says.

External service

Claude (Anthropic API)

Writes Study-Bot's explanations and the bots' chat, and picks a bot's plan from a fixed list. If the AI is off or over budget, pre-written lines and keyword matching take over.

One action, end to end: asking a bot to follow you

In a practice meeting you type “Kevin, follow me”. Kevin answers in the chat and, after the meeting, walks with you.

Reference route: three stops in the code

Not toured hands-on; follow it any time. Open the files in your editor and search for the anchor text.

  1. Your message leaves the browser

    client/src/screens/Meeting.tsx, search socket.emit("chat:send". The chat form sends your text to the server over Socket.IO. In practice games, someBot fills the hint in the chat box.

  2. The referee checks it, then the bots hear it

    server/src/app.ts, search socket.on("chat:send": it calls GameRoom.chat (server/src/game/GameRoom.ts), which only allows chat from living players during a meeting. When the message is sent to the room, bots.get(room.code)?.hear(m.fromId, m.text) passes it to the practice bots.

  3. A bot answers and makes a plan

    server/src/bots.ts, search hear(fromId: picks one or two bots (or the one you named) and asks botReply in server/src/ai.ts. Claude must answer in the shape of REPLY_SCHEMA, with a plan from PLAN_KINDS only. Without the AI, keywordReply does the same job. Then adopt( checks the plan against the game (a real room, a real player, never a vote against the speaker), and followPlan( carries it out after the meeting.

    The fixed list Claude must choose from 
    export const PLAN_KINDS = ["follow", "meet", "search", "avoid", "vote", "none"] as const;

A practice to reuse

Let the AI pick; let your code decide. Turn every play-test surprise into a rule and a test.

What happened: in play-testing, bots voted the player out just for mentioning the piece “What colour”. Claude had misread the message as a request to vote for the speaker.

What fixed it: Claude can only choose from a fixed menu (PLAN_KINDS, enforced by REPLY_SCHEMA), and the game checks every choice before acting on it (adopt( in server/src/bots.ts ignores a vote for the person speaking). A test now guards it: “ignores a plan to vote for the person who is talking” in server/src/bots.test.ts.

On your next project: when an AI feature does something surprising, describe what you saw and what you expected (a screenshot helps). Then ask the agent for two things: a rule in code that blocks the bad case, and a test that recreates it. The AI stays creative, and the rules stay in your code.

Run it again

npm install
npm run dev        # development: game at http://localhost:5173
npm run build
npm start          # production: http://localhost:3001, or $PORT
npm test           # unit tests
npm run sim        # bots play a full game
npm run ai:check   # a few real Claude calls (needs ANTHROPIC_API_KEY in .env)

To use Claude, copy .env.example to .env and add your own key. Never commit .env.
